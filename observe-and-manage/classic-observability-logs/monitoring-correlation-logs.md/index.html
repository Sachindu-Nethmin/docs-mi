# Monitor Correlation Logs Product observability enables rapid debugging of product issues. The WSO2 Integrator: MI enables observability using Correlation logs. Correlation logs allow you to monitor individual HTTP requests from the point that a message is received by the WSO2 Integrator: MI until the corresponding response message is sent back to the original message sender. That is, the complete round trip of an HTTP message (client →WSO2 Integrator: MI → back-end →WSO2 Integrator: MI → client) can be tracked and analyzed using a log file. When Correlation logs are enabled for the WSO2 Integrator: MI server, a separate log file named `correlation.log` is created in the `<MI_HOME>/repository/logs/` directory. Every HTTP message that flows between the WSO2 Integrator: MI and external clients goes through several state transitions. A new log entry is created in the `correlation.log` file corresponding to the state changes in the round trip of a single HTTP request. A Correlation ID assigned to the incoming HTTP request is assigned to all the log entries corresponding to the request. Therefore, you can use this Correlation ID to easily locate the logs relevant to the round trip of a specific HTTP request and, thereby, analyze the behavior of the message flow. ## Enable Correlation logs ### At the server start-up You can enable Correlation logging by passing a system property. - If you want Correlation logs to be enabled every time the server starts, add the following system property to the product start-up script (stored in the `<MI_HOME>/bin/` directory) and set it to `true`. ```bash -DenableCorrelationLogs=true \ ``` - Alternatively, you can pass the system property at the time of starting the server by executing the following command: - On **Linux/MacOS/CentOS**: `sh micro-integrator.sh -DenableCorrelationLogs=true` - On **Windows**: `micro-integrator.bat -DenableCorrelationLogs=true` Now when you start the WSO2 Integrator: MI, the `correlation.log` file is created in the `<MI_HOME>/repository/logs/` directory. ### During the runtime - You can enable correlation logging by invoking the configs resource of the Management API. For more information, see [enable/disable correlation logs using the Management API]({{base_path}}/observe-and-manage/working-with-management-api/#enabledisable-correlation-logging-during-runtime). - Alternatively, you can enable correlation logging using the Integration Control Plane. - You cannot disable the correlation logs during runtime if the correlation logs are enabled using the system property. !!! Tip You can customize the behavior of correlation logging, including the name of the HTTP header used for the Correlation ID, the log file location, and other related settings. For full configuration details, see [Configure Correlation Logs]({{base_path}}/observe-and-manage/classic-observability-logs/configuring-log4j2-properties/#correlations-logs). ## Send an HTTP request with a Correlation ID When a client sends an HTTP request to the WSO2 Integrator: MI, a Correlation ID can be included using the configured correlation header. By default, this header is set to `activityid`. !!! note If the client does **not** include a Correlation ID in the request, the WSO2 Integrator: MI will automatically generate one and assign it to the request. The Correlation ID, whether provided by the client or generated by the WSO2 Integrator: MI, is added to all log entries related to the same request. This helps you trace the complete flow of the request across the system. To change the default correlation header, see [Configure Correlation Logs]({{base_path}}/observe-and-manage/classic-observability-logs/configuring-log4j2-properties/#correlations-logs). The following is a sample POST request sent using the curl client. Note that the Correlation ID is included in the request header. ```bash curl -X POST --data @request.json http://localhost:8280/healthcare/categories/surgery/reserve -H "Content-Type:application/json" -H "activityid:correlationID" ``` ## Access Correlation logs If you know the Correlation ID of the HTTP request that you want to analyze, you can isolate the relevant logs as explained below. 1. Open a terminal and navigate to the `<MI_HOME>/repository/logs/` directory where the `correlation.log` file is saved. 2. Execute the following command with the required Correlation ID. Replace `<correlation_ID>` with the required value. ```bash cat correlation.log | grep "<correlation_ID>" ``` Shown below is an example of Correlation log entries corresponding to the round trip of a
